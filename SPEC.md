# Coffee Rush (browser) — ТЗ (соло, правила как в настолке)

## 0) Дисклеймер по IP
Эта реализация должна использовать **собственные** названия, тексты, иконки/арт. Механика — “как в настолке”, но **без копирования** фирменных материалов.

## 1) Режим игры
- **Платформа**: браузер (desktop-first), современный Chrome/Firefox/Safari.
- **Игроков**: 1 (соло).
- **Длительность**: пока игрок не получит 5 штрафов.
- **Game Over**: при получении **5-го penalty** (штрафного заказа), **немедленно** завершить партию.

## 2) Термины и сущности

### 2.1 Ingredient Board (поле ингредиентов)
- Размер: **4×4**.
- В каждой клетке — тип ингредиента (8 типов):
  - `coffee`, `milk`, `steam`, `ice`, `chocolate`, `caramel`, `tea`, `water`
- Раскладка поля задаётся данными (`boardLayout`).
- Некоторые клетки считаются **special** (для апгрейдов). Это также задаётся данными (`specialCells`).

### 2.2 Meeple (фигура игрока)
- Один meeple, стоит на одной клетке поля.

### 2.3 Ingredient Tokens (ингредиенты)
- Получаются при движении по полю.
- На шаге Move ингредиенты складываются в “собрано за ход” (`collectedThisTurn`).

### 2.4 Cups (чашки)
- У игрока **3 чашки**.
- Ограничения:
  - Нельзя вынимать из чашки отдельные ингредиенты.
  - Можно **полностью опустошить** любую чашку (все ингредиенты возвращаются в Supply).
  - Можно **не разливать** часть собранных ингредиентов, а вернуть их в Supply.

### 2.5 Order Cards (карты заказов)
- Каждая карта содержит список требуемых ингредиентов (обычно 2–4).
- Заказ выполнен, когда **состав одной чашки** совпадает с требованиями карты **точно** (по типам и количеству).

### 2.6 Player Board (очередь заказов по табам)
- 4 таба: `tab1`, `tab2`, `tab3`, `tab4`.
- В конце хода происходит “Flow of Time”:
  - все карты сдвигаются на 1 таб вниз;
  - карты, уходящие ниже `tab4`, становятся штрафами (`penalties`).

### 2.7 Rush Tokens
- Ресурс, который можно тратить на шаге Move.
- Каждый токен даёт **+1 шаг** к лимиту перемещения в этот ход.
- Получение: при падении заказов в штрафы — получить Rush Tokens **равно числу штрафов, полученных в этот момент**.

### 2.8 Upgrades
- В начале хода можно активировать апгрейд, если есть **≥3 выполненных заказа**:
  - сдать (discard) **ровно 3** выполненных заказа → активировать **1** апгрейд.
- Апгрейды описываются данными и реализуются как “модификаторы правил”.

## 3) Setup (соло)
- Сформировать колоду заказов (перемешать).
- Раздать стартовые заказы (как стартовому игроку в настолке):
  - `tab1`: 2 карты
  - `tab2`: 1 карта
  - `tab3/tab4`: пусто
- Поставить meeple на любую клетку поля.
- Получить ингредиент стартовой клетки и поместить его в чашку (выбор чашки игроком).

## 4) Ход игрока (строго по шагам)

### 4.1 Activate Upgrades (опционально)
- Если в `completedOrders` ≥ 3:
  - выбрать 3 карты → discard → активировать 1 апгрейд.

### 4.2 Move
- Базово можно сделать **1–3 шага**.
- Каждый шаг: перейти в соседнюю клетку (N/S/E/W). Диагональ — только если апгрейд активен.
- За **каждый шаг** (каждое “приземление” на клетку) получить 1 ингредиент этой клетки в `collectedThisTurn`.
- Можно тратить Rush Tokens: каждый токен увеличивает максимальное число шагов на 1.

### 4.3 Pour Ingredients
- Разложить все `collectedThisTurn` по чашкам и/или вернуть часть в Supply.
- Разрешено опустошать любые чашки целиком.

### 4.4 Process Order
- Игрок может выполнить до **3** заказов за ход (по числу чашек).
- Для каждого выполнения:
  - выбрать заказ + чашку;
  - проверить точное совпадение;
  - при успехе: заказ → `completedOrders`, чашка очищается (ингредиенты возвращаются в Supply).

#### Соло-адаптация “нагрузки на следующих игроков”
В настолке за каждую выполненную карту **следующие 2 игрока** берут по 1 новой карте в `tab1`.

В соло:
- если в этот ход выполнено `k` заказов, то игрок добирает **`2*k`** новых карт из колоды и кладёт их в `tab1`.
- если колода закончилась — просто добрать сколько есть; игра **не** заканчивается от пустой колоды (в соло-режиме конец только по 5 штрафам).

### 4.5 Flow of Time
- Сдвинуть все карты на 1 таб вниз.
- Карты, “выпавшие” ниже `tab4`, становятся penalty:
  - переместить в `penalties`
  - выдать Rush Tokens = количеству карт, ставших penalty в этот момент.
- Если после этого `penalties.length >= 5` → Game Over.

## 5) Контент и данные (MVP)

### 5.1 boardLayout (пример формата)
```json
{
  "boardLayout": [
    ["coffee","milk","steam","ice"],
    ["chocolate","coffee","water","milk"],
    ["tea","caramel","coffee","steam"],
    ["water","tea","ice","chocolate"]
  ],
  "specialCells": [{"r":0,"c":0},{"r":2,"c":1}]
}
```

### 5.2 orderCards (пример)
```json
{
  "id": "latte",
  "name": "Latte (placeholder)",
  "ingredients": ["coffee","milk","steam"],
  "tags": ["basic"]
}
```

### 5.3 upgrades (MVP набор)
Для MVP достаточно 4 апгрейдов, отражающих примеры из правил:
- `diagonalMove`: разрешает диагональное движение.
- `doubleCorner`: если meeple находится в угловой клетке при сборе ингредиента, получить **2** (вместо 1) с этой клетки.
- `doubleSpecialCell`: если meeple находится на special-клетке, можно взять **2 special ингредиента** (из набора `caramel/chocolate/tea/water`) вместо 1.
- `doubleOnOverlap`: (для мультиплеера) игнорируется в соло или используется как “если стоишь на special” — можно заменить, чтобы не держать бесполезный апгрейд.

## 6) UI/UX требования (MVP)
- Видимы одновременно:
  - поле 4×4
  - 4 таба заказов
  - 3 чашки и их состав
  - Rush tokens, penalties (0–5), completed count
  - текущая фаза и кнопки перехода
- Перемещение meeple:
  - клик по доступной клетке = шаг (1 клетка).
  - отображать доступные клетки подсветкой.
- Pour:
  - перетаскивание или клики по ингредиентам “собрано за ход” → выбранная чашка.
  - кнопка “Empty cup” на каждой чашке.
- Process:
  - выбрать заказ, затем выбрать чашку (или drag чашки на карту).

## 7) Acceptance Criteria
- Все шаги/ограничения соблюдены.
- За каждый шаг Move выдаётся ингредиент клетки.
- Нельзя частично вынимать ингредиенты из чашки.
- Соло-добор после выполнения: `2*k` карт в `tab1`.
- Penalty сдвигается из `tab4` вниз, выдаёт Rush, и при 5 penalty — Game Over.
